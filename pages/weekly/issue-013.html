The tool that said yes to everything

A permissions check that returned true for any user the agent named, and the forty-one accounts it quietly opened up before anyone looked.

September 18, 2026
Ines Okafor Applied ML
5 min read

An internal IT agent could grant access to shared folders. Before granting, it called a tool named can_grant with the requester and the folder. The tool returned true or false, and the agent was told to refuse on false.

It never refused once in three weeks. That should have been the first clue.

The failure

A check that could not say no

A refactor had changed the tool's signature from a user ID to an email address. The agent kept passing names, as in "grant Priya access to finance-q3". The lookup failed to find a user, the error handler defaulted to the folder's public setting, and every folder in that workspace had been created with public set to true by a migration years ago.

Every call succeeded. Every call returned true.

For your team

A guard tool that has never returned its negative answer in production is not tested by production. Look at the distribution of every yes or no tool your agent relies on.

The check

Watch the answers, not just the calls

Sift now tracks the result distribution of boolean tools per agent. A guard that has answered the same way for a thousand calls in a row gets a flag, with the first call where the distribution changed. In this case that was the day of the refactor.
