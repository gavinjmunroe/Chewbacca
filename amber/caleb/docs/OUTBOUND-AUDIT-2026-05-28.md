# Outbound Audit (2026-05-28)

PR-I belt-and-suspenders audit. Every outbound `sendMessage(...)` call site in
`Newton/agent/lib/`, `Newton/agent/agent.js`, and `Newton/agent/server.js` was
classified by where its `to` argument originates from. Three classes:

- **SAFE** — `to` derives from one of:
  - `tenant.phoneNumber` (the resolved tenant owner)
  - inbound webhook `from` (the contact who just texted us this turn)
  - a downstream propagation of one of the above (e.g. `normFrom`, a
    `sendOpts.tenant` flow through bootstrap-prepass / rave-master)
- **GATED** — `to` is hardcoded or derived from a configurable env / config
  field, but is protected by an explicit allow gate (admin token, allowlist,
  Sagar-only event flag).
- **NEEDS_FIX** — `to` could deliver to a phone unrelated to the current
  tenant/contact under any believable production state.

The runtime invariant added in `lib/transport.js` (this PR) is the
belt-and-suspenders layer on top of this static review: any send whose `to`
matches neither `tenant.phoneNumber` nor the inbound webhook contact emits a
`[outbound-audit][cross-tenant]` WARN line, and 5+ such sends in one minute
trigger a `[outbound-audit][alert]` error line.

## Findings

- 0 NEEDS_FIX. Every call site routes either to the resolved tenant owner or
  to the inbound webhook contact, with the exception of explicitly gated
  paths (admin tokens, opt-in allowlists, per-tenant config fields).
- Hardcoded `SAGAR_PHONE` no longer exists as a literal in rave-master; the
  Sagar destination is `tenant.phoneNumber` resolved through the
  Samber tenant record. The historical concern from 2026-05 was a literal
  `SAGAR_PHONE = "+15550100004"` constant; that was removed when rave-master
  was refactored to use `tenant.phoneNumber` (the Samber tenant resolves to
  Sagar's own phone). Belt-and-suspenders: rave-master is still
  `isRaveMasterEnabledForTenant`-gated and `RAVE_MASTER_ENABLED=1` env-gated.
- Cross-tenant runtime invariant (transport.js) is the second line of
  defense in case a future code change passes the wrong `to` argument
  through one of the SAFE paths.
