# Video library format

A creator's library is one Markdown file per video plus an index. It's where ideas get checked against what already happened. Keep it outside the skill, in a folder the profile names.

## Index (`README.md`)

One row per video, newest first, linking to its file. Columns: posted date, format, runtime, views, average watch (% of runtime), skip rate, % still watching at 10 s, non-follower share of views, follows per 1,000 viewers, and status (posted, not posted, unknown). Under that, a retention table with every video's curve at the same seconds, so their shapes can be compared.

Each video's file holds the full numbers. The index repeats only the columns above, so update both when numbers change.

## One file per video

Name it after the project folder, for example `2026-09-22-opus-55.md`. Sections:

1. **Header table:** project folder, final render and runtime, captions file (the source for lining up the curve), posted date and where, format, stake (who it reaches), and links to edit notes or reflections.
2. **Story:** the hook with its timing, then the beats with the time each starts. Quote the first two sentences exactly. For the rest, a line per beat is enough; the captions file holds the full text.
3. **Analytics:** snapshot date and time, the summary counts, the rates with their labels, views by source, and retention at fixed seconds. Write "not captured" for anything missing, never a guess.
4. **Reflection:** what worked, where people left (each cliff with its passage), what reach and conversion say, and the lesson, naming the hypotheses it supports or weakens. Label anything that isn't backed by this video's numbers as an opinion.

A video that wasn't posted gets the same file with a checklist review in place of analytics, labelled as a review, not evidence.
