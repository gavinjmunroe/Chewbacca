Sift Weekly·Issue 012

Context that went stale at step nine

A travel agent quoted a fare it had fetched eight steps earlier, after a later search had already shown the price change.

September 11, 2026
Theo Banerjee Co-founder
4 min read

A booking agent searched for a fare at step one, explored three alternatives, came back to the first option at step nine, and quoted the customer the price from step one. A search at step six had already returned the same flight at a higher price.

The customer booked, the card was charged the new price, and the complaint arrived within the hour.

The failure

Two values for one fact

The run held two prices for one flight. The model picked the earlier one, probably because it sat next to the flight details in the context, while the later price arrived in a long list of other results.

Neither value was invented. The answer was still wrong, because it used a fact the run itself had already replaced.

For your team

When a tool can return a value that changes over time, prices, stock, availability, put the fetch time in the result. It costs a few tokens and gives the model, and you, a way to tell which value is current.

The check

Latest value wins

Sift links each fact in the final answer to every step that mentions it. If a later step gives a different value, the answer is flagged as using stale support, with both steps shown side by side.
