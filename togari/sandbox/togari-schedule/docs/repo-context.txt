TOGARI-CLAY — REPO CONTEXT FOR LLM PROMPTING
==============================================
Last updated: 2026-05-04

PURPOSE
-------
togari-clay is a GTM (Go-To-Market) MCP server focused on the Opportunity Engine —
continuous signal monitoring and one-time contact data pulls for Blue Modern Advisory's
healthcare sales operations. Built on the Model Context Protocol (MCP), it integrates
Clay, Exa, Gmail, Slack, Stripe, and BigQuery into an automated prospecting pipeline.

TECH STACK
----------
- Runtime: Node.js 20+, TypeScript strict mode
- Protocol: MCP (Model Context Protocol) via @modelcontextprotocol/sdk
- AI: Anthropic Claude API (@anthropic-ai/sdk) for outreach drafting, classification
- Database: Google BigQuery (project: midyear-glazing-485303-u3, dataset: togari_data_lake)
- Validation: Zod schemas throughout
- Build: esbuild (custom build.mjs), outputs CommonJS to dist/
- Deploy: Railway (railway.json), supports stdio + HTTP/SSE transports
- Shared infra: @togari/admin (local package in packages/togari-admin/ — JWT auth, event streaming, Sentry, rate limiting)

KEY ARCHITECTURAL PATTERNS
--------------------------
1. MCP Tool Registration:
   server.tool(name, description, zodSchema, asyncHandler)
   Each agent file exports a register function that takes McpServer.

2. Provider Pattern (services/providers/):
   ToolProvider interface → BaseToolProvider → concrete providers (Clay, Exa, etc.)
   Central ToolRegistry with circuit breakers and rate limiting per provider.

3. BigQuery as Source of Truth:
   All persistent state in BigQuery. Parameterized queries throughout.
   Row-level security with client_id tenant isolation.

4. Governance Layer:
   Theology-aware content validation, Six Dimensions health framework.
   CAN-SPAM/HIPAA compliance checks. Email blacklist. Volume limits.

5. Dual Transport:
   MCP server supports stdio (Claude Desktop) and HTTP/SSE (web clients).
   Express app handles webhooks + REST API alongside MCP.

EXTERNAL INTEGRATIONS
---------------------
- Clay API: Company/contact enrichment, webhook ingest, HTTP API callbacks (10 calls/min, Enterprise tier)
  NOTE: Clay does NOT support programmatic table creation, "Find Companies" search, or "Job Posting" signal via API. These require Clay UI.
- Exa API: Web search for companies, job postings, recruiter LinkedIn profiles (100 calls/day)
- Structify API: Data normalization
- Gmail API: Email sending, thread reading (OAuth)
- Google Calendar API: Calendar sync (OAuth)
- Slack API: Bot messaging, thread replies
- Stripe API: Checkout sessions, webhook events for payment status
- Anthropic Claude API: Outreach drafting, reply classification (claude-sonnet-4-6)
- Fireflies.ai: Meeting transcripts (ingest + normalization)
- GCP Secret Manager: Production secrets
- GCP Cloud Monitoring + Pub/Sub: Observability, event streaming

OPPORTUNITY ENGINE V2 (NEWEST SUBSYSTEM)
-----------------------------------------
Two-product architecture:

A) Signal Subscriptions — continuous monitoring:
   - Clients describe target via natural language query (e.g. "healthcare companies hiring data engineers in Texas")
   - Claude parses NL → structured params (industries, titles, locations, company sizes)
   - Exa web search discovers matching contacts + companies
   - Clay enriches contacts (email, phone, LinkedIn, company data)
   - New contacts stored in togari_structured_contacts, deduped by email
   - Frequency: daily / weekly / biweekly (configurable per subscription)
   - Notifications via Email, Slack, or both
   - Stripe metered billing: Starter $40/mo (50), Standard $60/mo (100), Professional $80/mo (200), Enterprise $150/mo (500)

B) One-Time Data Pulls — ad hoc contact list exports:
   - Client submits NL query + desired count (up to 10,000)
   - Pipeline: NL→BigQuery SQL against togari_structured_contacts datalake
   - Shortfall enriched via Exa + Clay
   - CSV generated and uploaded to GCS
   - Stripe one-time payment (tiered: $0.50/contact first 250, $0.30 for 251-1000, $0.20 for 1001+)
   - Download link emailed when ready

Webhook flow: Framer form → /webhooks/framer-subscription OR /webhooks/data-pull → Stripe Checkout → /webhooks/stripe → cron or async processing
8 MCP tools: signal_create/list/update_subscription, signal_trigger_scan, signal_get_results, create/get/list_data_pulls
3 REST endpoints: POST/GET /api/data-pulls, GET /api/data-pulls/:pull_id

BIGQUERY TABLES
---------------
- contacts — prospect/contact records
- togari_structured_contacts — enriched contact datalake (name, email, title, company, LinkedIn, phone)
- deals — pipeline deals with stage tracking
- audit_log — all system actions for compliance
- opportunity_subscriptions — notification engine subscriptions (V2: signal_query, monitor_frequency, companies_limit)
- notification_history — delivery records with cost tracking
- data_pull_requests — one-time data pull tracking (status, CSV URL, cost)
- signal_results — signal query result history (matched contacts, Exa results)
- signal_subscriptions — VIEW aliasing opportunity_subscriptions
